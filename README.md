# trail_run_analysis

用手表导出的 GPX 轨迹分析越野跑比赛：单场概览、跨场次的坡度表现对比、同路段/同路线逐段对比，以及 3D 地图回放。

有两套东西：

- **Python 脚本**（下面各节）：独立的脚本，直接运行，没有安装步骤，也没有命令行框架。
- **网页版**（[web/](web/README.md)）：一个可以单独发给别人的 `.html` 文件，用浏览器打开、把轨迹文件拖进去就能用，不需要 Python。计算口径和 Python 脚本一致，另外支持 GPX 1.0、TCX、停留分析、2D / 3D 地图和 ITRA 估分，页面里自带使用教程。心率、步频、步幅，以及上下坡、爬坡耐力、掉速点、和基准场比这几项分析只有网页版有。

## 目录结构

```
trail_run_analysis/
├── core/      基础模块：GPX 解析、坡度采样、轨迹空间匹配（其他脚本都依赖它）
├── compare/   当前在用的对比图
├── maps/      3D 地图 HTML 生成
├── legacy/    早期版本的对比脚本和它们生成的图
├── data/      输入的轨迹文件
├── output/    compare/ 和 maps/ 的输出（每次运行覆盖同名文件）
└── web/       网页版，见 web/README.md
```

## 环境

- Python 3.7 及以上（开发时用的是 3.13）。
- 唯一的第三方依赖是 matplotlib：`pip install matplotlib`。
- 除 `core/analyze.py` 和 `legacy/compare.py` 外，所有脚本都需要 matplotlib，包括不画图的 `core/compare_segments.py` 和两个地图脚本，因为它们用到的 `track_label` 定义在 `core/plot_grade.py` 里。
- 图中的中文使用 Microsoft YaHei 或 SimHei 字体。在没有这两种字体的系统上，中文会显示成方块，需要修改各脚本开头的 `plt.rcParams["font.sans-serif"]`。
- 两个地图 HTML 打开时需要联网，用来加载 MapLibre GL JS、Esri 卫星影像和 AWS 地形瓦片，都不需要 API key。

## 快速开始

脚本内部按自身位置找 `data/` 和 `output/`，所以在哪个目录下运行都可以。

```powershell
python core\analyze.py            # 每场的概览和每公里分段，打印到终端
python compare\plot_scatter.py    # 坡度-表现散点图
python compare\plot_gap.py        # 坡度调整配速随比赛进度的变化
python compare\same_route.py      # 同一条路线的两场逐公里对比
python maps\build_map_live.py     # 3D 同步回放，生成后用浏览器打开 output\map3d_live.html
```

不带参数时，多场脚本读取 `data/` 下的全部 GPX，两场对比脚本使用写死的默认组合（见下表）。也可以把 GPX 路径作为参数传入。

## 脚本一览

### core/

| 脚本 | 作用 | 参数 | 输出 |
|---|---|---|---|
| `analyze.py` | 单场概览（距离、耗时、移动时间、配速、爬升、海拔范围、心率、踏频）和每公里分段表 | `[a.gpx ...]`，默认全部 | 终端 |
| `compare_segments.py` | 找出两条轨迹同方向的公共路段，逐段对比用时、配速、移动配速 | `[A.gpx B.gpx]`，默认骆驼三峰 25-10 对三峰 25-11 | 终端 |
| `plot_grade.py` | 坡度对配速、垂直速度、心率、效率的曲线，前半程实线、后半程虚线 | `[a.gpx ...]`，默认全部 | `legacy/grade_performance.png` |

这三个文件同时是其他脚本的库：

- `analyze.py` 提供 `parse_gpx`、`haversine`、`fmt_hms`、`fmt_pace`。
- `plot_grade.py` 提供 `grade_samples`（坡度采样）和 `track_label`（文件名到比赛标签的映射）。
- `compare_segments.py` 提供 `load`、`build_grid`、`match_sequential`、`find_segments`、`moving_time`。

### compare/

| 脚本 | 作用 | 参数 | 输出 |
|---|---|---|---|
| `plot_scatter.py` | 坡度对水平速度、垂直速度、心率、速度/心率的散点图，叠加分桶中位数和 25~75 分位带；水平速度图上有 Tobler 徒步函数作参照 | `[a.gpx ...]`，默认全部 | `output/grade_scatter.png` |
| `plot_gap.py` | 把坡度影响消掉后的等效平地速度（GAP），以及 GAP/心率，随比赛进度的滚动中位数 | `[a.gpx ...]`，默认全部 | `output/gap_progress.png` |
| `plot_segments.py` | `compare_segments.py` 的图形版：平面轨迹上高亮公共路段、沿公共路段的累计时间差、各段移动配速柱状图 | `[A.gpx B.gpx]`，默认同 `compare_segments.py` | `output/segments.png` |
| `same_route.py` | 两场路线基本相同时的对比：每隔固定距离设检查点，输出分段表；图中有按掉速率着色的 3D 路线、连续累计时间差、局部配速 | `[A.gpx B.gpx] [检查点间距 km]`，默认三峰 25-11 对三峰 26-03，间距 1.0 | 终端和 `output/same_route.png` |

两场对比里，A 是基准，时间差都是 B 减 A，正值表示 B 更慢。

怎么选：两场只有部分路段重合时用 `compare_segments.py` / `plot_segments.py`；整条路线相同时用 `same_route.py`；路线完全不同时只能用 `plot_scatter.py` 和 `plot_gap.py` 这类按坡度归一化的图。

### maps/

| 脚本 | 作用 | 输出 |
|---|---|---|
| `build_map.py` | 所有轨迹叠加在卫星影像和真实地形上的静态 3D 地图。可点击图例显示/隐藏轨迹，调地形夸张倍数，点起点标记看该场统计 | `output/map3d.html` |
| `build_map_live.py` | 所有比赛同时发枪的同步回放。面板实时显示各场的距离、最近约 60 秒配速、心率、海拔、累计爬升；可调倍速、拖动进度、镜头跟随某一场；底部是海拔-时间剖面，点击可跳转 | `output/map3d_live.html` |

两个脚本都接受 `[a.gpx ...]`，默认全部。轨迹数据直接嵌在 HTML 里，每 5 个点取 1 个。

### legacy/

早期版本，保留备查。`compare.py` 仍可正常运行。

| 脚本 | 作用 | 输出 |
|---|---|---|
| `compare.py` | 多场指标对比表：等效距离配速（距离 + 爬升/100 m）、爬升速率 VAM、下坡配速、速度/心率效率、前后半程衰减、五档坡度分桶配速 | 终端 |
| `plot_diff.py` | 各场中位速度曲线，以及相对最强一场的速度差 | `legacy/grade_diff.png` |

## 计算口径

所有脚本共用下面这些定义，改动时需要保持一致（它们在几个文件里各写了一遍，没有集中成常量）。

| 概念 | 定义 |
|---|---|
| 距离 | 相邻点的 haversine 水平距离累加，不计高差 |
| 移动 / 停留 | 相邻两点间速度大于 0.3 m/s 算移动，否则算停留 |
| 海拔平滑 | 前后各 5 个点的滑动平均 |
| 累计爬升 / 下降 | 对平滑后的海拔使用 3 m 迟滞阈值：相对上一个参考点变化满 3 m 才计入 |
| 坡度样本 | 沿移动距离每累计约 50 m 取一个样本，记录坡度、速度、平均心率、平均踏频、距离进度；遇到停留就丢弃当前窗口重新开始 |
| 比赛进度 | 已跑距离占全程距离的比例，前半程/后半程按 50% 划分 |

`compare_segments.py` 里的分段爬升是例外：它对原始海拔直接用 3 m 阈值，没有先平滑。

### GAP（plot_gap.py）

1. 把传入的所有场次的坡度样本汇合，按 2% 坡度分桶取速度中位数（每桶至少 20 个样本），除以最接近 0% 那一桶的值，得到坡度成本曲线 f(坡度)，桶之间线性插值。
2. 每个样本的 GAP = 实际速度 / f(坡度)。
3. 对每场按进度做滚动中位数，窗口为 8% 进度，步长 2%。

成本曲线是用传入的数据自己拟合出来的，所以 GAP 只在同一次运行的场次之间可比。换一批输入，曲线和数值都会变，也不能和 Strava 等平台的 GAP 直接比较。

### 轨迹匹配（compare_segments.py）

1. 把 B 的点放进 50 m 网格。对 A 的每个点，在周围 3×3 个格子里找距离小于 50 m 的 B 点作为候选。
2. 在候选中选「距离 + 0.05 × 与上一个匹配索引的差」最小的点。这个惩罚项让匹配沿 B 的同一趟连续推进，B 在折返路段多次经过同一地点时不会来回跳。连续 15 个以上的点没有候选时，重置连续性。
3. 公共路段 = 连续匹配的一段，允许中间最多 15 个点匹配不上，长度至少 400 m，且 B 的索引超过 70% 是递增的（同方向）。

相关常量在 `compare_segments.py` 开头：`MATCH_R`、`CELL`、`GAP_PTS`、`MIN_SEG`。

### 同路线对比（same_route.py）

沿 A 每隔一个间距取检查点，在前后 200 m 内找最近的已匹配点。然后按 B 的索引取最长递增子序列，丢掉顺序错乱的检查点。相邻检查点之间比较 A 和 B 的用时，表中两边的配速都按 A 的分段距离计算。

图里的掉速率是累计时间差对距离的导数（±250 m 中心差分），单位 min/km。色标按掉速率绝对值的 75 分位裁剪（代码注释写的是 90 分位，实际是 0.75）。

读图时注意：时间差是按总耗时算的，没有扣除停留。累计时间差曲线上的竖直台阶、局部配速图上的尖峰，对应的是 B 在原地停留（或手表暂停记录），不是跑得慢。默认的三峰 25-11 对三峰 26-03 里，2 分钟以上的台阶有 9 个，合计约 34 分钟，占总差距 109 分钟的三成左右。3D 图上的深红色同样混着停留。

## 数据要求

脚本按 COROS 导出的 GPX 1.1 编写，现有 5 个文件都是每秒一个点。

- 每个轨迹点必须有 `<ele>` 和 `<time>`，缺失时脚本会直接报错。
- 心率和踏频读取的是 `gpxdata` 命名空间下的 `<gpxdata:hr>` 和 `<gpxdata:cadence>`。其他品牌常用的 `gpxtpx:TrackPointExtension` 读不到，心率相关的图和列会是空的。
- 输出里的日期时间按运行脚本的那台机器的本地时区显示。

## 添加一场新比赛

1. 把 GPX 放进 `data/`。
2. 在 `core/plot_grade.py` 的 `track_label` 里加一条「文件名关键字 → 标签」。列表按顺序匹配，取第一个命中的，所以更具体的关键字要放在前面（现在「三峰2603」排在「三峰」前面就是这个原因）。不加的话，标签会是文件名的前 14 个字符。
3. 场次超过 5 场时，给颜色列表补颜色，见下一节第 1 条。
4. 重新运行需要的脚本。图和地图里的场次按开始时间排序，颜色也按这个顺序分配。

## 已知问题

1. **颜色列表只有 5 种，正好够现在的 5 场。** 颜色和场次是用 `zip` 配对的，多出来的场次没有颜色，也没有任何提示：画图脚本会直接漏掉时间最晚的场次，地图脚本会把它写进 HTML 但不给颜色值。加第 6 场时，需要给这 7 个脚本的颜色列表各补一个：`core/plot_grade.py`、`compare/plot_scatter.py`、`compare/plot_gap.py`、`legacy/plot_diff.py`、`legacy/plot_fade.py`、`maps/build_map.py`、`maps/build_map_live.py`。
2. **`same_route.py` 会漏掉起点附近的路段。** 起终点在同一处时，A 刚出发的点会匹配到 B 回程的点，这些检查点随后被当作顺序错乱丢掉。默认的三峰 25-11 对三峰 26-03，分段表从 2 km 处开始，合计只覆盖 A 全程 22.15 km 中的 19.9 km。图上的 ▲ 和「0k」标记因此画在了 2 km 处，而不是真正的起点。
3. **`compare_segments.py` 和 `plot_segments.py` 的默认 B 取决于文件列举顺序。** 代码取的是文件名含「三峰」且不含「骆驼」的第一个文件，现在是 `251116三峰(1).gpx`。`data/` 里有两个这样的文件，新增文件后默认值可能变化，需要确定结果时请显式传入两个路径。
4. **两场对比脚本的参数个数不对时不会报错。** `compare_segments.py` 和 `plot_segments.py` 只在恰好传入 2 个参数时使用它们，其他情况一律回退到默认组合。
5. **`core/plot_grade.py` 的图保存在 `legacy/` 而不是 `output/`。**
6. **`legacy/` 里的三张图是旧的。** 它们生成时脚本还只有 4 种颜色，所以每张最多画了 4 场；其中 `grade_performance.png` 和 `grade_diff.png` 的生成时间还早于三峰 26-03 的 GPX 加入 `data/` 的时间。重新运行对应脚本会得到 5 场的图，颜色分配也会和旧图不同。
7. **`legacy/plot_diff.py` 的线型图例对三峰 26-03 不成立。** 左图标题写的是「实线=2025，虚线=2026」，但代码按标签是否以「骆驼」或「三峰」开头来判断，2026 年的三峰 26-03 也会画成实线。
