# 网页版：越野跑轨迹分析

[越野跑轨迹分析.html](越野跑轨迹分析.html) 是一个可以单独分发的网页文件。双击用浏览器打开，把轨迹文件拖进去就能看分析，不需要安装任何东西，也不需要 Python。

要给别人用，把这一个 `.html` 文件发过去就行。

## 怎么用

1. 用浏览器打开 `越野跑轨迹分析.html`。
2. 载入轨迹，三种方式都可以，都支持一次多个：
   - 点「选择轨迹文件」；
   - 点「选择文件夹」，会读出文件夹里（含子文件夹）所有的 `.gpx` / `.tcx`；
   - 把文件或文件夹直接拖到页面上。
3. 上方的轨迹列表里可以勾选哪些轨迹参与图表、改名字、改颜色、移除。
4. 点导航栏切换面板。

文件只在本机浏览器里读取和计算，不会上传。

页面自带「使用教程」标签，没有载入轨迹时默认显示它，第一次载入轨迹后自动跳到「概览」。把网页发给别人时不需要另外附说明。

两场对比不会把所有轨迹两两匹配一遍。每条轨迹有一个中心点（经纬度外框的中心）：默认选中心点最近的一对，时间早的作 A；选定 A 以后，B 的列表按中心点离 A 的距离从近到远排列，并自动选中最近的一条。只有选中的这一对会做轨迹匹配。

## 心率、步频、步幅

文件里带了心率或步频就参与分析，没有的地方表格显示 `--`、图是空的，其他分析不受影响。

- **步频**：每分钟迈多少步，两只脚都算，只统计在迈步的时间（步频读数大于 0 的那些秒）。
- **步幅**：一步迈出去的距离 = 迈步并且在移动的时候走过的距离 ÷ 这期间的步数。「在移动」和移动时间用同一个门槛（速度大于 0.3 m/s）。
- **心率**：按时间加权的平均值。
- 相邻两个点隔了 30 秒以上（暂停、掉信号）的空档，三项都不计。
- 一段里迈步时间不到 5 秒不给步频，不到 10 步不给步幅。

文件里的步频有两种写法：有的手表记一只脚每分钟落地的次数（80 上下），有的记两只脚（160 上下）。页面取一条轨迹里所有非零步频的 90 分位数，低于 112 就当成单脚的，整条乘以 2。这是经验判断：全程都在走、两只脚合计的步频又正好在 100~112 之间的轨迹，可能被误判成单脚而翻倍。

出现的位置：

| 位置 | 内容 |
|---|---|
| 概览 | 全程平均步频、步幅 |
| 每公里分段 | 每公里的步频、步幅 |
| 海拔与速度 | 步频、步幅曲线，每 250 米（横轴为时间时每 2 分钟）取平均 |
| 坡度表现 | 坡度对步频、坡度对步幅两张图 |
| 两场对比 | 公共路段表、每公里检查点表里各有「心率 A / B」「步频 A / B」「步幅 A / B」三列；整条路线对比多三张沿路线的曲线图（50 米一个点，取前后各 250 米的平均） |

现有 5 场的全程平均：步频 157 / 148 / 139 / 133 / 130 步/分，步幅 0.63 / 0.62 / 0.69 / 0.55 / 0.68 米（顺序同下面 ITRA 表）。这 5 个文件都是 COROS 导出的单脚步频，两只脚写法的文件只用构造的数据测过。

## 和基准场比、上下坡、掉速点

这一组分析参考了一份现成的跑步分析清单，做法按现有的 5 场数据重新验证过，和原清单不完全一样。不一样的地方在本节最后列出。

### 和基准场比（概览）

选一场当基准，记作 100。其他各场的五项各算成基准场的百分之几，「综合」是五项的平均。勾选或取消别的轨迹不影响这些数字，换基准场才会变。默认的基准是日期最早的一场。

| 项目 | 算法 |
|---|---|
| 等效速度 | （距离 + 爬升 ÷ 100 米）÷ 总耗时，含停留 |
| 上坡爬升速率 | 坡度 ≥5% 的移动路段里每小时爬升的米数 |
| 平路速度 | 坡度 ±5% 以内的移动路段的速度 |
| 下坡速度 | 坡度低于 -5% 的移动路段的速度 |
| 后半程保持 | 后半程速度 ÷ 前半程速度，按坡度对齐后算（见下面「后半程对前半程」） |

某一项算不出来（比如路线上没有下坡）时，综合按剩下的几项平均，表里会注明。

现有 5 场，以三峰 25-11 为基准：骆驼 105，三峰 25-11 100，三峰 26-03 74，澜跑 77，FUGA 84。

同一条路线的两场，五项都可以直接比。路线不同时，平路和下坡的速度很看路面，这两项和综合只能当参考。

### 爬坡耐力（坡度表现）

对 50、100、200、300、500 米五个高度，在全程里找一对点：后面的比前面的高出至少这么多米，而且两点之间用时最短。爬升速率 = 高度 ÷ 这段用时。

- 用的是平滑后的海拔（前后各 5 个点）。
- 中途停下来的时间算在里面。
- 只要求净升高够数，中间可以有小的起伏；有起伏的段用时更长，自然不会被选中。
- 算出来超过 4000 m/h 的段当作海拔数据跳变，不取。这只能挡住明显的跳变，海拔数据本身有毛病时结果仍可能偏高。
- 路线上没有这么高的坡时那一档空着。

现有 5 场（m/h）：

| 比赛 | 50 米 | 100 米 | 200 米 | 300 米 | 500 米 |
|---|---|---|---|---|---|
| 骆驼三峰 25-10 | 1047 | 1006 | 934 | 900 | 878 |
| 三峰 25-11 | 1192 | 1084 | 994 | 976 | 884 |
| 三峰 26-03 | 968 | 874 | 800 | 790 | 710 |
| 澜跑 26-09 | 741 | 669 | 613 | 497 | 435 |
| FUGA香山 26-11 | 804 | 753 | 637 | 595 | 没有这么高的坡 |

### 上下坡

**上坡、平路、下坡**只按路线本身（里程和海拔）来分，不看时间，所以同一条路线的两场分出来的段是一样的：

1. 每 50 米一格，每一格的坡度取它和前后各一格（约 150 米）的平均；超过 +3% 算上坡，低于 -3% 算下坡，其余算平路。
2. 连着的同类格子合成一段。
3. 从最短的开始，把不到 150 米的小段并进相邻的段：两边同类就三段合一，否则并进较长的一边。
4. 合并完按整段的平均坡度重新归类，相邻同类的再合一次。

表里的时间和速度只算移动时间。爬升（下降）速率 = 这些路段净升（降）的米数 ÷ 移动时间。它和概览里的「上坡爬升速率」不是一个口径（那个是按坡度 ≥5% 的 50 米样本算的），两个数不一样是正常的。

**大坡**是另一种分法，给「逐个看每个大坡」用：从一个低点到下一个高点（下坡反过来），中途反向不超过 30 米的算同一个坡，净升降 100 米以上才列出。一个大坡里可以夹着平路，所以平均坡度会比上面的上坡段缓。

现有 5 场的路程占比（上坡 / 平路 / 下坡）：骆驼 44 / 2 / 54，三峰 25-11 50 / 3 / 47，三峰 26-03 45 / 7 / 47，澜跑 38 / 18 / 43，FUGA 45 / 15 / 41（%）。

### 走势和掉速点（坡度修正配速）

用的是面板里已有的等效平路速度（每个 50 米样本的速度 ÷ 换算曲线在这个坡度上的值）。

- **开头、最后**：前 25%、后 25% 路程的中位数。
- **全程走势**：把全程按路程分成十段，各取中位数，拟合成一条直线，报告终点相对起点的变化。
- **掉速点**：沿进度取滚动中位数（窗口 8%，步长 2%）。从终点往回看，滚动中位数连续低于「开头」的 88% 的那一段的起点，就是掉速点。最后一个滚动点（覆盖 92%~100%）不看，因为终点前常有冲刺；这一段至少要有 8% 的路程，否则不算。

掉速点依赖换算曲线，而换算曲线是用当前勾选的轨迹拟合的，所以换一批轨迹，掉速点可能挪动。

现有 5 场一起勾选时：骆驼、三峰 25-11 没有掉速点；三峰 26-03 在 62%（第 13.6 公里），澜跑在 34%（第 8.1 公里），FUGA 在 50%（第 9.5 公里）。

### 后半程对前半程（坡度修正配速）

按路程对半分，比同一种坡度上的速度。直接比有个问题：同是「陡升」一档，前半程可能平均 25%，后半程平均 17%，速度差一截但不是因为累。所以档内再按每 5% 细分：

1. 两个半程的 50 米样本各按 5% 一档归类（-40% 以下、+40% 以上各并成一档）。
2. 只取两个半程都至少有 3 个样本的细档。
3. 每个细档的权重是两个半程在这一档的路程之和。两个半程各自按这套权重算平均配速，再换成速度。

所以表里的速度是「按同样的坡度构成」算的，和坡度表现里各档的配速不完全一样。这部分不用换算曲线。

概览里的「后半程保持」是同一个算法不分档的结果。现有 5 场：0.98、0.95、0.79、0.71、0.87。

### 时间差出在哪种坡度上（两场对比）

只在两条路线重合 80% 以上时做。两场走的是同一段路，所以不需要任何坡度模型：

1. 沿用整条路线对比里的检查点，每两个检查点之间按 A 的里程切成约 100 米的小段，用轨迹匹配找到 B 上对应的那一段。
2. 每个小段按 A 的平滑海拔算坡度，归到五档（和坡度表现里的五档相同）。
3. 每档累计 A、B 各自的移动时间。

各档相加正好等于两场的移动时间之差，再加上停留之差就是总用时之差。

三峰 25-11（A）对三峰 26-03（B）：

| 坡度 | 路程 | B - A | 占移动时间差 |
|---|---|---|---|
| 陡降 <-15% | 5.79 km | +19.7 分 | 37% |
| 缓降 -15~-5% | 4.13 km | +12.9 分 | 24% |
| 平路 -5~5% | 2.23 km | +6.0 分 | 11% |
| 缓升 5~15% | 2.51 km | +6.3 分 | 12% |
| 陡升 >15% | 5.30 km | +8.2 分 | 15% |
| 移动时间合计 | 19.95 km | +53.1 分 | |
| 停留 | | +56.0 分 | |
| 总用时 | | +109.0 分 | |

B 上对应的小段是靠轨迹匹配找的，匹配在相邻小段之间可能有几秒的错位，所以单独一档的数字会有出入，合计不受影响。把 A、B 对调，各档的占比会变（陡降 31%、缓降 22%、平路 18%、缓升 20%、陡升 9%），因为对调后对上的路程多了开头 2 公里，小段的切法也不同。

### 和那份清单不一样的地方

| 清单里的做法 | 这里的做法 | 原因 |
|---|---|---|
| 每场用三次多项式拟合「坡度 → 速度」，再算反事实用时 | 没有做 | 用这 5 场验证：三次曲线在 +28%~+36% 的坡度上速度降到 0 以下，而三峰 25-11 有 53 个样本比 ±30% 还陡；留出 1/5 路段检验，预测用时的误差是 7.5%~46%。洛伦兹曲线（3 个参数）和分档法的误差在 4%~10%，但把一场的曲线用到另一条坡度范围更宽的路线上，结果仍然取决于怎么外推 |
| 综合表现指数：五项各自缩放到 0~100 再平均 | 以一场为基准记 100，各项算成它的百分比再平均 | 缩放到 0~100 的做法，勾选的轨迹一变所有分数都跟着变（去掉一场，其余最多变 18 分） |
| 指数里有「上坡跑动时间占比」 | 换成了「平路速度」 | 占比接近 0 时算百分比会失真：2.6% 对 16.9% 会被算成 15 分；三峰 26-03 以三峰 25-11 为基准，把「平路速度」换成它，综合会从 74 掉到 63 |
| 进步归因：两场各坡度段的速度差，换算成每公里节省的时间 | 只在同一条路线的两场之间做，直接比同一小段路的用时 | 不同路线之间，同一坡度段里的坡度并不一样（「陡上」一段，三峰 25-11 平均 24.7%，FUGA 平均 17.5%），细分以后有的档连正负号都会变 |
| 上下坡段：坡度 ±3%，最短 60 米；长坡 = 单段爬升 ≥150 米 | 坡度 ±3%，最短 150 米；大坡另按「中途反向不超过 30 米、净升降 ≥100 米」找 | 按 3% 分出来的段会被坡中间的平台切开，不适合当作「一个大坡」 |
| 崩点：比中位配速慢 12% 以上的公里 | 掉速点：等效平路速度持续比开头慢 12% 以上的起点 | 原始配速主要反映坡度；这里要回答的是「从哪里开始一路慢到底」 |
| 制动指数 = 陡降速度 ÷ 缓降速度 | 没有做 | 缓下坡也慢的时候比值反而高：5 场里最慢的三峰 26-03 指数最高（0.74），最快的骆驼最低（0.55） |

清单里没有做的还有：跑动包络、缓坡持续跑、上下坡衔接损失、配速区间分布、最佳努力、弯曲度、海拔分带、能量模型、心率分区和 TRIMP。

以上验证只有一个人的 5 场数据。

## ITRA 估分

这是按速度做的估算，不是 ITRA 官方的算法，结果只能当参考。官方用的是赛事公布的距离和爬升，还会按每场完赛者以往的水平单独校准。

### 怎么算的

1. 把爬升折成距离：每爬升 100 米算 1 公里，加到实际距离上，得到「等效距离」（单位写作 ekm）。
2. 等效距离 ÷ 总耗时 = 等效速度。总耗时包含中途停下来的时间，和比赛成绩的算法一样。
3. 和「1000 分的人在同样长的比赛里能跑多快」比：估分 = 1000 × 等效速度 ÷ 1000 分对应的等效速度。

### 1000 分对应的等效速度：六档数字

比赛越长，再厉害的人也跑得越慢，所以这个速度不是一个固定的数。面板最上面有六个输入框，分别是等效距离为 20、40、80、120、160、250 时的取值：

| 等效距离 (ekm) | 20 | 40 | 80 | 120 | 160 | 250 |
|---|---|---|---|---|---|---|
| 默认值 (ekm/h) | 22.5 | 21.4 | 19.8 | 18.3 | 17.0 | 15.0 |

长度在两档之间的比赛，按等效距离的对数在相邻两档之间线性取值；比 20 短的按第一档算，比 250 长的按最后一档算。面板里的第二张图画的就是这条曲线，载入的比赛标在上面。

默认值里只有 40 这一档有依据：它是用三峰 25-11 的实际分数 452 反推的（42.4 ekm，用时 4:24:59，等效速度 9.60 ekm/h）。其余五档是凭印象给的粗略数字，没有用实际分数验证过，长距离比赛的估分可能整体偏高或偏低。网页里只有这六个数，没有写这个分数。

六个数字可以直接改，改完马上生效。页面只接受合理的输入：

- 每个数要在 10 到 30 之间；
- 短距离的数不能比长距离的小（可以相等）。

不符合时，出问题的格子变红并说明原因，表格和图继续按上一组合法的数字计算；「撤销改动」回到那一组数字，「恢复默认」回到上表。

### 用自己的比赛标定

如果知道某一场的实际分数，在面板里选中那一场、填上分数（50 到 1000 之间）、点「标定」。页面把六个数字按同一个比例放大或缩小，让这一场的估分正好等于实际分数，其他比赛的估分也跟着变。如果按这个分数调整后有数字会超出 10 到 30 的范围，页面会拒绝，并提示检查分数和选的比赛是不是对应的。

六个数字和标定状态存在浏览器本地，不存分数。

现有 5 场的结果：

| 比赛 | 等效距离 | 等效速度 | 默认值估分 | 误差 | 用 452 标定后 | 误差 |
|---|---|---|---|---|---|---|
| 骆驼三峰 25-10 | 29.9 | 10.26 ekm/h | 469 | ±60 | 470 | ±37 |
| 三峰 25-11 | 42.4 | 9.60 ekm/h | 452 | ±59 | 452（实际分数） | |
| 三峰 26-03 | 39.7 | 6.37 ekm/h | 298 | ±46 | 298 | ±33 |
| 澜跑 26-09 | 36.3 | 6.43 ekm/h | 298 | ±45 | 299 | ±32 |
| FUGA香山 26-11 | 28.0 | 7.52 ekm/h | 342 | ±48 | 343 | ±32 |

默认值和标定后几乎一样，是因为默认的 40 这一档本来就是用同一场比赛反推的，标定时六档只乘了 0.9989。这 5 场都在 XS 组，长度相近，所以这张表检验不了曲线在其他长度上对不对。

### 误差有多大

「误差」是估分大概会偏多少，可以粗略理解为：真实分数大约有三分之二的可能落在「估分 ± 误差」之内（统计上叫 1σ）。它由几项互不相关的误差合成（平方相加再开方）：

| 误差来源 | 大小 | 什么时候算 |
|---|---|---|
| 「1000 分对应的等效速度」本身不准 | 分数的 ±10% | 没标定时 |
| 爬升量不准（手表气压计和官方数据有出入） | 分数 × 10% × 爬升在等效距离里占的比例 | 始终 |
| ITRA 每场单独校准，不是套一个固定公式 | ±25 分 | 始终 |
| 公式本身的简化（速度和分数并不完全成正比） | ±20 分 | 没标定时 |
| 同一组别里路线长短不同 | ±17.5 分 | 标定后 |

前两项跟着分数走，所以分数越高误差越大。把鼠标停在表里「误差」那一格上，可以看到每一项各是多少。

标定只在同一个 ITRA 组别内可靠。和标定用的比赛不在同一组别的轨迹，估分仍用标定后的六档数字，但误差按没标定算。

### 误差里没算的偏差

- 官方公布的距离和爬升通常比手表记的小，实际分数会因此再低 10~20 分。
- 80 及以上那几档的默认数字没有验证过。估长距离比赛时，最好先用一场长度相近、知道实际分数的比赛标定。

这些误差的大小都是当初分析时估的经验值，只有三峰 25-11 这一个实际分数可以对照，没有用更多比赛验证过。

## 支持的文件格式

| 格式 | 说明 |
|---|---|
| GPX 1.1 | 现在大多数手表和 App 导出的格式 |
| GPX 1.0 | 老设备的格式，元素名相同，扩展字段直接写在轨迹点下面 |
| TCX | Garmin Training Center（TrainingCenterDatabase v2），COROS、佳明等都能导出 |

不支持 FIT（二进制格式）和 KML。

具体读法：

- **一个文件里有多条轨迹时逐条载入**：GPX 的每个 `<trk>`、TCX 的每个 `<Activity>` 和 `<Course>` 各算一条。同一条里的多段（`<trkseg>`、`<Lap>`）首尾相接，段与段之间的空档算作停留。
- **路线和航点**：GPX 里没有 `<trk>` 时才读 `<rte>`（规划路线，通常没有时间，只出现在海拔图和地图里）。`<wpt>` 和 TCX 的 `<CoursePoint>` 当作航点，画在地图上。
- **命名空间前缀不影响读取**：`<trkpt>` 和 `<gpx:trkpt>` 都认。
- **时间**：按规范是 UTC；没写时区的也按 UTC 处理。
- **没有定位的点会被跳过**（TCX 在暂停或丢星时会写这种点）。
- **个别点缺海拔**时沿用前一个有效值。

从轨迹点里读的字段：

| 数据 | 认的元素名 |
|---|---|
| 心率 | `hr`、`heartrate`、`heart_rate`；TCX 的 `HeartRateBpm/Value` |
| 步频 | `cad`、`cadence`、`RunCadence`、`run_cadence`（单脚、双脚两种写法的处理见上面「心率、步频、步幅」） |
| 温度 | `atemp`、`temp`、`Temperature` |
| 手表里程 | `distance`；TCX 的 `DistanceMeters` |

这些名字不管带什么前缀（`gpxtpx:`、`ns3:`、`gpxdata:` 或不带）都能读到，覆盖了佳明 TrackPointExtension v1/v2、ClueTrust（COROS 用的）和旧版佳明 GpxExtensions v3。

不读的字段：`speed`、`course` / `cog`、`bearing`、`depth`、`wtemp`。速度由坐标和时间计算，其余和跑步分析无关。

「手表里程」只在概览里和按坐标算出的距离并排显示，所有分析都用按坐标算的距离。现有 5 场里手表里程都更长，多出 0.3~1.0 km（2~5%）。

## 地图

地图默认不加载，点「打开 2D 地图」或「打开 3D 地图」才会联网。

### 图源

| 图源 | 本机测试 | 备注 |
|---|---|---|
| 高德 卫星 | 2D、3D 都出图 | 高德是国内偏移坐标，页面自动换算。地址不是官方公开接口，以后可能失效 |
| 高德 卫星+路网标注、高德 街道 | 2D 出图，3D 没试 | 同上 |
| Esri 卫星影像 | 2D、3D 都出图 | |
| Esri 地形图 | 2D 出图，3D 没试 | |
| Esri 街道、Esri 山体阴影 | 地址能访问，没有在页面里试过 | |
| OpenStreetMap、OpenTopoMap、CARTO | 在开发用的网络下连不上，没有测过 | 需要能访问这些站点的网络 |
| 自定义地址 | 没有测过 | 填 `https://.../{z}/{x}/{y}.png` 这种带三个占位符的地址；是偏移坐标的话勾上对应选项 |
| 无底图 | 能用 | 完全不联网 |

### 2D

拖动平移，滚轮或双指缩放，双击放大。鼠标停在轨迹上显示那一点的里程、时间、海拔、坡度、速度、心率。

### 3D

地形起伏来自 AWS 上公开的全球高程瓦片（Terrarium，地址是 `s3.amazonaws.com/elevation-tiles-prod`），贴图来自所选图源，两者互不依赖。高程瓦片连不上时，地面退回平面，轨迹高度用文件里的海拔，页面上会有一行提示。

操作：

- 拖动旋转，右键或 Shift+拖动平移，滚轮缩放；手机上单指拖动旋转，双指缩放和平移。
- 旋转始终绕着画面正中心对着的那块地面。每次按下鼠标、滚动滚轮、手指落下或点「+」「−」「俯视」时，页面沿画面中心的视线找到它和地形的交点，把旋转中心移到那里，镜头本身不动。
- 左右拖动时，地面跟着手走：在画面下半部（靠近自己的一侧）按下往右拖，近处的地面往右转；在上半部（远处）按下往右拖，远处的地面往右转，两种情况镜头转的方向相反。方向在按下的那一刻定下来，拖动途中不变。

可以调地形夸张倍数和贴图清晰度。

地形范围是轨迹的外框再往外扩 10 公里，分两级精度画在同一张网格里：

- 内圈（轨迹外框加少量留白）：细网格，用最细一级的高程瓦片，单独一张贴图。「贴图清晰度」调的是这一张。
- 外圈（再往外 10 公里）：网格从内圈边缘起逐格放大 12%，最粗 300 米一格，用低一级的高程瓦片和另一张贴图。

以现有的三峰路线为例：内圈 10.6 × 7.1 km，外圈 30.6 × 27.1 km，网格 409 × 303，内圈一格约 33 米。打开时镜头只框住内圈，拉远才能看到外圈。

「地形范围」可以选全部勾选的轨迹，或只看某一条。勾选的轨迹相距超过 30 km 时，默认只取第一条，否则地形范围太大看不清。

选「无底图」时不联网：地面是带 1 km 网格的平面，轨迹高度用文件里的海拔。

### 着色和标记

- **着色**：按轨迹、速度、比坡度预期快/慢、坡度、心率。「比坡度预期快/慢」是把每一段的速度按坡度换算后，和这条轨迹自己的中位水平相比，红色是慢、绿色是快、灰色是停留。
- **停留点**：2D 里是圆圈，越大停得越久，3 分钟以上标出分钟数；3D 里是立柱，每停 1 分钟高 30 米。
- **公里标**：只在 2D 里有，间距随缩放变化。
- **航点**：黄色菱形，不超过 80 个时写出名字。

### 隐私

打开地图后，浏览器会向图源请求这一带的底图瓦片，对方因此能知道你在看哪个区域。轨迹数据本身不会发出去。

## 和 Python 版的关系

计算口径和 `../core`、`../compare` 下的脚本一致。`tests/check_core.js` 用现有 5 个 GPX 把两边逐项对过：单场概览和每公里分段的每一行、坡度样本的每个数值、成本曲线、GAP 滚动中位数、轨迹匹配数组、公共路段表、同路线分段表，全部相同。

网页版多出来的：

- 停留列表和停留地图；
- 和基准场比、爬坡耐力、上下坡分段和大坡、走势和掉速点、后半程对前半程、同路线时间差按坡度拆开。Python 版都没有，没有可以对照的参考结果，`check_core.js` 里用构造的轨迹和手算的数验证，再加真实文件上的自洽性检查（比如各档相加等于总数）；
- 整条路线对比里把时间差拆成「移动时间差」和「停留差」；
- 上坡爬升速率、下坡配速、各坡度档配速按坡度样本汇总（只含移动中的数据）。这几项的算法和 `../legacy/compare.py` 不同，数值不一样；
- GPX 1.0 和 TCX、多轨迹文件、航点、温度、手表里程。Python 版只认 COROS 写法的 GPX 1.1。

网页版没有的：Python 版 `same_route.py` 里的 3D 掉速热力图（用 3D 地图加「比坡度预期快/慢」着色代替），以及 `maps/build_map_live.py` 的同步回放。

## 已知问题和限制

- **只在桌面版 Chrome 157 里测过。** 代码只用了 ES5 语法和很早就有的浏览器接口，没有用任何第三方库，按理说 Edge、Firefox、Safari 和国产浏览器都能跑，但没有逐个验证。
- **没有在手机上测过。** 页面做了窄屏布局，在 390 像素宽的窗口里检查过。手机上直接打开本地的 `.html` 文件可能受限（比如在聊天软件的预览里脚本不运行），这时需要用浏览器打开，或者把文件放到任意一个网页空间上再访问。
- **起终点重合的路线，对比时可能漏掉开头一段。** 刚出发的点会被配到对方的回程上。现有的三峰 25-11 对三峰 26-03，整条路线对比是从第 2 公里开始的。Python 版有同样的问题。
- **参数是按每秒一个点的数据调的。** 海拔平滑、轨迹匹配里的「允许连续 15 个点匹配不上」等都按点数算，对几秒甚至更久才一个点的记录，结果会偏粗。
- **轨迹很多时图表会很挤。** 下拉栏和两场对比已经按大量轨迹处理过，但概览表、各张图和图例仍然是每条勾选的轨迹一行或一条线，几十条以上建议只勾选要看的。
- **掉速点会随勾选的轨迹变。** 它用的换算曲线是当前勾选的轨迹一起拟合的。
- **上下坡分段、大坡、掉速点的阈值是按现有 5 场调的**（3%、150 米、30 米、100 米、慢 12%）。这 5 场都是山地越野，17~24 公里；平缓的路线或者超长距离上合不合适没有验证过。
- **爬坡耐力依赖海拔数据的质量。** 没有气压计、只靠卫星定位测海拔的记录，短的那几档（50、100 米）可能偏高。
- **3D 标签不做遮挡判断**，山背面的标签也会显示。
- **3D 贴图需要图源允许跨域读取。** 不允许的图源在 3D 里会退回按海拔着色，2D 不受影响。

界面的样式约定，写在 `style.css` 开头：

做法借鉴航空安全卡片：

- **颜色**：深蓝 `#14284b` 用于所有文字和描边；内容区是白色，页面背景是浅灰 `#f4f4f1`。另有四种纯色，各管一件事：黄 `#ffe01b` 是主要按钮和重点词，蓝 `#35b8ee` 是选中、悬停和图示里的轨迹线，红 `#e3262f` 只用于箭头和警告，琥珀 `#f2b84b` 只用在教程的一个标题栏上。鲜艳的颜色只出现在小面积上。
- **描边**：容器、按钮、输入框一律 2px 深蓝实线；内容区里面的分隔线是 1px 浅灰。
- **平涂**：不用渐变，不用阴影。
- **圆角**：6px 或 8px，不超过 8px；只有步骤编号是圆形。
- **字体**：标题和编号用 DIN 一类的标识字体（Windows 上落到 Bahnschrift），正文用 Inter / Helvetica / Arial 加系统中文字体。都是系统自带字体，页面里没有嵌字体文件，没装的机器会用列表里的下一个。
- **教程**：五个板块各是一个带标题栏的独立方框，标题栏颜色依次是深蓝、蓝、黄、琥珀、灰，板块内部不出现别的板块的颜色。「三步开始」用圆形编号、红色箭头和线条图示，每格一句话。
- **图标**：全部是写在页面里的 SVG 线条图，导航栏的图标从教程卡片上复制，不用图片文件和图标字体。
- **表格**：每张数据表有标题（`<caption>`），用 `app.js` 里的 `setTable(id, 标题, 行)` 生成。

以上各条（除了具体色值）在 `browser_test.js` 里有检查。

`release/` 里是以前发出去的三个版本，都不是构建产物，`build.py` 不会动它们：`越野跑轨迹分析_可用_v1.html` 是改成这套设计之前的一版，`越野跑轨迹分析_可用_v1.1.html` 是设计改完的一版，`越野跑轨迹分析_release_v2.0.html` 和当前构建内容一样。
